# 按需工程规则

本文件保留实现与验证的专项约束；由根 AGENTS.md 按任务路由，不要求每次全文读取。产品中的审批指用户对业务动作的授权，不是要求编程代理逐步申请本地编辑或测试许可。

## 4. 工程地图与依赖边界

仓库已包含三端工程与四个共享包。存在代码不代表依赖已安装、平台已构建或完整流程已通过；每轮以现场检查为准。

| 目录 | 职责与约束 |
|---|---|
| `apps/mobile` | React Native + Expo + Expo Router；移动交互、权限与平台适配 |
| `apps/desktop/src/main` | Electron 主进程、窗口与受限系统能力 |
| `apps/desktop/src/preload` | 最小、明确的 IPC 桥接接口 |
| `apps/desktop/src/renderer` | React 页面；不直接访问数据库、文件系统或平台密钥 |
| `apps/server` | Node + Fastify；现有 Mock 接口不代表生产鉴权或真实 AI 已完成 |
| `packages/domain` | 纯 TypeScript 领域对象、业务规则、命令/查询与仓储接口 |
| `packages/contracts` | Zod 运行时校验、版本化命令和跨边界协议 |
| `packages/ai` | AI 执行器、能力接口与确定性 Mock；供应商 SDK 不泄漏到领域层 |
| `packages/adapters` | 本地 SQLite 与应用命令入口；Node 驱动仅从 `/node` 入口提供 |
| `docs`、`planning` | 决策、工作包、验收定义与执行证据 |

- 表中列出目录职责，不代表相关能力已全部实现；领域接口不能证明审批、幂等和正式写入已完成。
- 依赖由应用与适配器指向共享契约和领域；领域不能反向导入应用或基础设施。`domain` 不依赖 React、React Native、Electron、Node 文件系统、数据库驱动或供应商 SDK。
- `contracts` 保持平台中立，不导入应用层。跨包通过公共导出访问，避免深层路径耦合与循环依赖。
- UI 与 AI 复用同一业务命令处理器；不在页面、IPC 或模型工具内各写一套正式写入逻辑。
- `packages/design-tokens` 属于架构规划，按当前切片需要再创建；不为填满目录树增加空包。
- SQLite 驱动、ORM 与生产同步选择受 SY-003 / ADR-004 验证约束；PowerSync、Supabase、Hermes 等候选不等于已采用。

## 5. 依赖、运行与构建

- 使用 pnpm workspace。Node 要求以根 `package.json` 的 `engines` 为准，pnpm 版本以 `packageManager` 为准；不要维护另一份容易漂移的版本表。
- 新增或升级依赖时查阅官方兼容资料，并以实际安装、构建验证。记录资料来源、日期及版本，不猜测“最新稳定版”，不把已有版本声明当成兼容性证明。
- 安装应生成并保留 `pnpm-lock.yaml`；已有锁文件的复现安装使用 `pnpm install --frozen-lockfile`。有意更新依赖时审查锁文件差异，不以删除锁文件或换包管理器掩盖失败。
- 原生依赖遵循当前 Expo SDK 的安装方式；不为了通过构建随意关闭类型检查或安全配置。

实际脚本与任务覆盖以根及相关包的 package.json 为准；执行入口与环境说明见 [BOOTSTRAP.md](BOOTSTRAP.md)。根 build/test 仅调度已定义的任务，不证明原生构建、签名、安装包或全平台验收。核对实际执行用例与结果。


## 6. 代码与交互实现

- UI 实施与审查先按 [UI 验收标准](design/ui-acceptance.md) 确定 S/M/L、适用 UI-V/UI-I 检查及证据范围；不把数值基线或截图生成当成验收通过。
- 视觉方向、设计工具及原型确认范围统一遵循 [DESIGN.md](../DESIGN.md)，复用已批准设计；历史技能安装和旧色板不构成当前实施要求。原型不替代正式实现与原生验收。
- UI 信息密度遵循 [DESIGN.md](../DESIGN.md)：熟悉操作优先图标，保留无障碍名称与足够触控区域；删除重复标题、口号和多余说明，低频入口不抢占主内容。简单文案或入口删减做必要静态检查，较复杂布局/交互变化再截图验收。
- 设计技能选择（维护者于 2026-09-06 明确）：本项目禁止使用 `ui-ux-pro-max`，不作为设计、实现或审查依据；该限制不要求卸载本机技能。
- 延续现有 TypeScript 严格配置、命名与格式。修改限于当前工作包和必要依赖，不做无关重构、全仓格式化或提前抽象。
- 外部请求、IPC、模型输出和持久化输入在边界做运行时校验；TypeScript 类型断言不构成数据校验或权限校验。
- 新领域行为明确空间、对象关联、状态转换、版本与错误语义；跨空间引用必须拒绝。
- 涉及协议或存储结构变更，说明 `schemaVersion`、兼容范围与恢复方案；不宣称未经测试的旧客户端兼容。
- 核心交互保留手动编辑、拒绝、取消与可恢复输入。按功能覆盖加载、空数据、离线、模型失败、权限拒绝、能力不支持、预算耗尽和冲突状态。
- 金额精度、日期与时刻、时区和统计范围按领域文档定义；复盘数字由正式数据计算，不能由模型猜测。

## 7. AI 草稿、审批与执行证据

```text
用户输入 → AI 草稿 → 预览/修改 → 有效审批 → 命令校验 → 事务写入 + 回执
                                            ↓
                                      拒绝/冲突/过期
```

- AI 未获批准只能提出或保存草稿；拒绝、取消、过期或撤销授权不得触发新的正式写入。
- 审批绑定执行身份、`spaceId`、动作范围、参数 hash、对象版本与有效期；参数或相关版本变化后必须重新确认，执行前再次校验权限。
- `commandId` 是幂等与对账标识。同 ID 同参数只产生一次副作用并返回已有执行结果；同 ID 不同参数明确报冲突，不覆盖历史回执。
- 正式数据、活动事件与命令回执按同一事务边界一致提交；写入后丢失响应先查询回执再决定重试，不直接重新创建对象。
- 成功以真实对象 ID、回执与正式查询结果为依据。模型文本、HTTP 成功或 Mock 返回不能单独证明业务动作成功。
- 断流、取消、后台中断和未知结果分别记录；已执行动作仍需对账，不能因界面取消就宣称已回滚。
- 模型能力不足返回明确的 `unsupported` 或相应错误，不自动切换未授权供应商。真实调用遵守已配置的供应商、预算和循环上限，未知用量不能写成零。
- 运行记录保留必要的模型/策略版本、状态和数据范围，不持久化隐藏思维链。Mock、真实 Provider 与正式执行分别验收。

## 8. 数据、安全与平台边界

- 本地模式由本机命令处理器正式写入；云端模型仅返回草稿。同步模式的服务端负责共享权限与版本裁决，本地已保存和云端已确认必须区分。
- 云端下发结果不得再次进入本地待上传队列。并发冲突保留可恢复输入，删除标记与旧端重放不能静默复活记录。
- 账号切换、退出、撤权须隔离缓存、队列、检索与待执行任务；不得把 A 空间数据发送给 B。
- 本地保存、同步、AI 外发、后台处理是不同用途的授权。个人资料、日记、录音、资产只按授权用途提供；不默认整库上传，不向未授权供应商发送用户数据。
- 平台密钥不得进入客户端；个人密钥不得写入 Git、日志、导出或测试快照。使用占位配置与合成样例，不读取或打印无关秘密。
- 记忆与学习反馈先作为候选；用户可确认、纠正、删除。来源删除或撤权后相关摘要和检索投影必须失效。
- Electron 保持 `contextIsolation: true`、`nodeIntegration: false`、`sandbox: true` 和受限导航；IPC 明确列出允许动作并校验参数、调用来源与权限，不暴露通用 Shell、文件系统或数据库执行入口。
- 模型文本和检索内容按不可信内容渲染。录音需授权、可中断且有文字替代；不宣称手机全天后台常驻或未实现的端到端加密。
- 数据迁移、导入、升级与恢复不能覆盖唯一原始数据；破坏性数据库操作需维护者明确授权，并具备可核实的恢复方案。

## 10. 验证与完成定义

- 工具选择按 [自动化优先策略](testing.md)：Playwright 覆盖并通过的同平台同场景，开发期间不重复 Computer Use。原生缺口优先现有脚本；确需视觉判断或原生诊断才定向使用 Computer Use。

- 完成标准以 [docs/acceptance.md](acceptance.md) 为准。先执行受影响包和业务路径的验证，再按跨包影响扩大检查；不要用重复运行无关检查代替真实结果。
- 业务、安全或数据行为变更必须有针对性验证，覆盖失败路径。涉及命令至少验证拒绝/过期审批、参数变化、重复提交、同 ID 不同参数、丢回执；涉及同步和权限再覆盖冲突、旧端重放、跨空间与撤权。
- 修复缺陷先复现或建立可靠失败证据，再验证修复结果。不要写只复述实现、没有可观察行为断言的测试。
- 纯文档变更检查路径、链接、命令与配置一致性、JSON 结构（如有修改）及 `git diff --check`；不因此声称应用测试通过。
- 分别记录静态检查、单元/集成测试、Mock、真实供应商、构建、模拟器、真机和发布工件状态。模拟器与编译不能替代 iOS/Android 真机验收；桌面发行按目标系统单独验证。
- 每项结果写明通过、失败、未运行或阻塞及原因，并保留准确命令、工作目录、相关运行时/设备版本和复现证据。工具不可用时交付可验证部分，不伪造输出。
- 跨用户泄露、密钥进入包体、重复重要写入、拒绝后执行、静默丢失数据或虚构完成，均阻止相关功能发布。
- 适用验证通过后停止重复验证；仅在新增修改、失败或未解决风险时扩大范围或重跑受影响项。共享证据必须对应相同代码/构建和适用场景，旧证据不得冒充本轮结果。

# 本地数据与同步决策

## 1. 核心不变项

本地优先意味着离线可读写、立即反馈和可导出，不意味着设备永远可信、不需要云端权限校验或天然端到端加密。

单用户多设备同样可能冲突。禁止全表统一 last-write-wins。同步引擎待验证，数据权威、幂等和删除语义则必须先明确。

## 2. 写入权威

Local mode：设备事务是正式写入。远程 AI 只能产生草稿和解释，由设备验证后执行。

Synced mode：设备离线产生 optimistic 命令及本地投影；服务器按身份、baseVersion、审批和 commandId 决定接受、拒绝或冲突。正式服务端回执与版本再投影到设备。

后台云端 AI 只可作用于已同步、被授权的数据，并由服务端命令处理器写入。其结果下发后不可被设备当作一条新的用户写入重新上传。

UI 至少区分：本地已保存、等待同步、已同步、冲突、服务端拒绝。离线操作被拒绝时保留可恢复草稿，禁止静默删除用户输入。

## 3. 幂等与事务

命令唯一键为 space/owner + commandId，服务端在同一事务中检查、写业务和保存回执。相同 commandId 不接受另一份 payload。

原始音频上传、对象存储与数据库不是同一事务；使用状态机、内容校验和清理任务处理失败，不能以数据库提交成功宣称文件已经上传。

审批通过不跳过上传后的服务端权限校验。客户端被篡改不能获得其他用户数据或平台额度。

## 4. 冲突分类

| 数据 | 策略基线 |
|---|---|
| 展示偏好 | 可配置字段级覆盖 |
| 项目与任务 | 基于版本的 patch；不同字段可合并，同字段冲突保留双方 |
| 学习会话与复习记录 | 独立追加、稳定 ID 去重 |
| 目标删除与旧端更新 | 删除标记优先阻止复活；恢复通过显式命令 |
| 日记/自由文本 | 首版冲突副本与人工选择，不静默覆盖 |
| 资产快照与交易修订 | 保留来源、修订与冲突；禁用无提示覆盖 |

过长时间离线的设备可能需要全量重建。删除标记清理前须有游标或同步 epoch 策略；旧设备不能通过重放旧记录复活删除数据。

## 5. 技术 PoC

候选 A：PowerSync React Native 与 Node SDK。验证真机构建、SQLite 生命周期、离线队列、服务端写入验证、取消/断线、账号切换、附件、许可和退出路径。[S08][S09][S10]

候选 B：设备 SQLite + 最小命令上传与服务端变更游标，用于评估控制力与维护成本；不是另起通用分布式同步框架。仅在 A 不满足关键条件时投入受限验证。

两条候选都不得以 demo 能同步两行数据即标记生产可用。选型结果写入 ADR-004，附版本、环境、重现步骤及失败项。若 PowerSync 采用自己的存储/投影方案，应用迁移按其原生机制设计，不假设能直接套用全部 expo-sqlite DDL。

## 6. 账号、密钥和导出

连接账号前显示本地空间与云端空间是否合并；账号切换先停止旧同步并清理旧授权，不能把旧数据重打标签归到新账号。删除同步账号与只断开同步是不同操作。

不同账号至少采用隔离的数据文件/空间策略，实际方式在 PoC 验证。令牌与模型密钥不进入业务表及同步队列。

导出包含版本化 JSON、可选 Markdown 与附件清单，明确缺失附件和范围；恢复导入要预览与去重。备份恢复后仍应尊重已有删除和撤权状态。

## 7. 发布门槛

存储 PoC 在 M1 完成。生产同步在 M3 通过验收后才宣称可用；即使生产同步尚未完成，单设备 Alpha 可继续验证，但应明确不具备多设备一致性保证。

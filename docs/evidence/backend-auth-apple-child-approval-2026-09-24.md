# Apple 家长批准儿童设备的再次验证 · 2026-09-24

工作树为 `feature/dev`。本批使用合成 Apple 身份、临时 PostgreSQL 和本地 HTTP；未连接真实 Apple、家庭设备或生产服务，未提交、推送、部署。

共享 Apple 再次验证动作白名单增加 `approve-child-device`。新增 `0014_apple_child_approval_reauth.sql` 仅增量替换 Apple flow 的动作与 purpose/session 绑定约束，保留既有迁移校验和。服务端沿用已有 Apple 身份验签与会话绑定流程签发该动作的一次性 reauth grant；儿童设备审批接口只消费匹配动作的 grant，错误动作不能批准，也不消费其原授权。

隔离验证：共享契约 **50/50**、服务端单测 **35/35**、Apple 再次验证集成 **14/14**、儿童配对集成 **11/11**、服务端全量集成 **191/191**。测试包含逐版本迁移、错误动作拒绝、有效 Apple grant 经真实本地 HTTP 批准后由儿童设备一次领取。`spec:check` **6/6**；完整终检结果以本轮最终检查为准。

客户端现已增加专用 Apple 批准尝试和家长控制器入口：先预览同一配对，再读取当前监护关系版本，经 Apple 授权取得动作绑定 grant 并发出一次批准。grant 仅在尝试闭包内传递；丢失 Apple 完成响应时沿相同完成键恢复，批准请求已发出且响应丢失时不自动重发。另有密码再次验证的同一控制器路径。适配器测试 **166/166**、移动端工厂测试 **149/149**；真实 Fastify、临时 PostgreSQL 与 Playwright 的设备配对用例 **6/6**，其中密码批准走完整控制器与 HTTP，Apple 批准仍是合成授权的服务端集成测试。全仓类型检查 **13/13**、`spec:check` **6/6**、`release:check` 与 `git diff --check` 通过。

这证明合成 Apple 授权及客户端受控路径可工作，不证明原生 Apple 授权或真实账号设备配对。正式界面、签名配置、真机及生产供应商验收仍未完成，SA-06/07/08 整体状态不改变。

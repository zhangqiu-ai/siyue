## 房间邀请的内部授权依据

增量迁移 `0023_room_invitations.sql` 新增独立于成人家庭成员邀请的房间邀请表。每个房间与受邀主体只有一项记录；受邀者须是该家庭有效成员，儿童可以用本人有效儿童设备会话接受。邀请绑定发起人的成员版本、家庭版本与期限，可在接受前撤销。内部仓储重新检查有效会话、开放房间、活跃家庭、双方成员及版本；已接受邀请在每次席位认领前由 `authorizeJoin` 复核，未接受、撤销、过期、家庭冻结、房间结束或成员退出均不能作为入房依据。对儿童还核对邀请人当前监护关系及同意；即使另一监护人让儿童会话保持有效，原邀请人的监护同意撤回后，其旧邀请也失效。

本切片仍是内部内核：`parentAuthority='verified'` 仅可由未来可信服务层依据 C11 判定后构造，客户端输入不能直接变成该值；当前没有房间 HTTP 路由、RTC 凭据或媒体连接。邀请有效期由未来授权调用方确定，逐人接纳、已加入者移除与邀请委托仍属 O01 待决。席位表的上限测试不能证明这些真实连接行为。

验证：`corepack pnpm --filter @siyue/server build` 通过；`node --test apps/server/tests/integration/room-invitations.test.mjs` **14/14**，覆盖真实儿童设备授权、邀请和接受、未邀／跨家庭／撤销／到期／结束／冻结／退出／版本变化、并发和回滚、0022→0023 增量迁移，以及“另一监护人仍有效但原邀请人撤回同意”的拒绝。代理完成初始 13 项时服务端全量集成 **439/439**；本轮追加第 14 项与对应校验后只复跑了邀请单文件，不把先前全量结果计作追加校验后的全量验收。没有可授权访问的房间路由，因此尚无房间功能的浏览器 E2E。

后续定向审查又复现一条旧邀请复活路径：受邀成员退出后，若同一成员行重新激活且家庭版本未变，原已接受邀请曾能再次通过 `authorizeJoin`。当前未提交的 0023 开发迁移补存受邀成员版本，创建、接受与加入均要求版本一致；版本变化即使成员再次有效也拒绝旧邀请。先运行新增用例见到“Missing expected rejection”，修复后服务端构建、邀请与注销清理隔离 PostgreSQL 联合 **38/38**、删除回执真实 HTTP Playwright 定向 **1/1** 通过。没有对持久开发库或生产库执行 0023 迁移；若外部环境已有旧 0023，必须另做增量迁移而不能覆写其校验和。

过期边界审查复现另一条问题：数据库时钟已过邀请期限，但调用方传入落后的 `now`，旧邀请仍能被接受或用于加入。现在取得家庭、房间、邀请行锁之后读取数据库 `clock_timestamp()`，判定和写入使用不早于数据库时间的时刻；调用方时间只能让过期判断更严格。新增用例先复现“Missing expected rejection”，修复后服务端构建及邀请隔离 PostgreSQL **16/16**。这仍未验证 RTC 服务商侧断开已在线连接。

当前一房间一受邀成员只有一条邀请记录；家庭或成员版本变化会使它安全失效，但在同一房间里不能重新邀请该成员。如何重新签发、保留已失效记录及向用户提示，需要在 O01 决定；此内部切片没有擅自开放重邀能力。

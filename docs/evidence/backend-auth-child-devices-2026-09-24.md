# SA-08 儿童设备服务端与隔离验收 · 2026-09-24

工作树：`feature/dev`，保留既有未提交改动。本批没有连接生产数据库、使用真实儿童资料、提交、推送或部署。

新增 `0011_child_device_pairing.sql`（增量迁移）和严格共享契约。当前家庭 owner/admin 可在明确同意及当前版本下创建受监护 child；child、家庭成员、同意和监护关系同事务提交，家庭版本递增。监护关系独立于 owner/admin/member 角色。匿名儿童设备申请生成两个独立随机秘密，仅将 keyed digest 落库：供家长识别的 requestToken 与只留在申请设备上的 pollSecret。申请五分钟到期并按地址、installation 和全局预算限流；状态响应只含生命周期与期限，轮询至少相隔三秒。

家长批准要求当前有效监护关系、关系版本、成人会话及动作绑定的 `approve-child-device` 再次验证。批准时记录关系与家长凭据版本；儿童设备以 pollSecret 一次领取后，才在同事务建立最长 30 天的设备授权与 child 会话。初始 `scopes=[]`，不自称已经取得房间、白板或记录权限。完成响应在 60 秒内可受控恢复；旧 refresh 已轮换或授权失效后不再返回旧凭据。儿童会话每次验证和刷新都读取当前授权、监护关系、同意记录、家庭与家长凭据版本。监护人撤销设备授权和关联会话失效同事务提交；即使旧 access 尚未自然到期，下一次请求也被拒。

本地验证：独立临时 PostgreSQL 的 `0010→0011` 迁移、约束和最小权限测试 4/4；连同监护创建、设备管理及配对集成测试合计 23/23，覆盖拒绝、版本漂移、双秘密分离、并发单次领取、丢响应恢复、刷新轮换后拒绝、同意撤回和即时撤权。全量服务端集成 **169/169**，修正了两处旧迁移测试对迁移条数/历史库当前会话服务的错误假设，并把邀请测试的合成 child 会话改为真实设备授权会话。真实 Fastify + 隔离数据库的 Playwright HTTP 测试 `children.spec.mjs`、`device-pairings.spec.mjs`、`child-devices.spec.mjs`、`families.spec.mjs` 合计 **12/12**；其中覆盖真实家长再次验证、儿童领取和撤权后会话 401、非监护人 404。共享契约测试 **47/47**、全仓类型检查 **13/13**、`corepack pnpm spec:check` **6/6**、`corepack pnpm release:check` 与 `git diff --check` 均通过。测试只使用合成账号与设备，不调用真实 Apple/SMTP/云端服务。

目前没有客户端配对和设备管理界面，也没有 iPhone/iPad/Android 真机配对证据；授权记录的空 scopes 不能加入真实房间或编辑共享白板。故只勾选 9.3a 服务端分片；9.3b、9.4、FAM-04～07 及 SA-08 整体验收仍开放。

## 同日增量：审批预览、安全复核与客户端接口

家长扫描后新增 `POST /v1/device-pairings/{id}/preview`：成人会话、申请令牌和拟授权儿童共同限定读取，服务端重新核对实际监护关系，只返回设备标签、平台、到期和儿童最小摘要；不返回 pollSecret，不消耗再次验证授权。正式批准仍需独立 `approve-child-device` 授权。共享契约和客户端适配器分别提供匿名申请/轮询/领取与成人预览/批准/设备管理接口，轮询和领取在同一客户端实例中拒绝并发重复请求。客户端适配器已验证，正式移动与桌面页面尚未接线。

独立安全复核后修正四项边界：

- 精确 720 小时授权与数据库日历 `30 days` 跨夏令时不一致。保留 `0011` 原校验和，以新 `0012_device_grant_exact_hours.sql` 增量替换约束；在 America/New_York 春季切换窗口证明 720 小时可写、超出 1 毫秒被拒，并验证从已应用 `0011` 的库继续迁移。
- 空授权 scopes 的儿童会话此前能凭家庭成员资格读取成人家庭摘要。现在两个 `GET /v1/families` 路由要求成人会话；真实 grant 的儿童会话仍有效，但该读取返回 403，成人读取不变。
- 匿名设备描述与儿童显示名在共享契约中拒绝 NUL、换行等 C0 控制字符；监护同意版本的契约格式与数据库一致，避免非法输入变成数据库 503 或预览文本多行伪装。
- 过期的 `family-children:` 幂等记录加入启动和定期定向清理，保留未过期记录及其他业务 scope。

随后补齐 `GET /v1/families/{id}/children`：只列出当前成人会话在该家庭实际监护且仍满足同意、成员资格和主体有效条件的儿童；家庭角色本身不产生可见儿童。家长端共用客户端提供 `listChildren`，并拒绝响应中混入其他家庭的儿童。移动端账号控制器已接入匿名申请、状态、领取与受限 child 会话持久化；丢失领取响应可在服务端允许的窗口内恢复，领取进行中不能取消并丢失回执。真实 HTTP 用例覆盖领取后冷启动恢复。正式配对页面与扫码尚未接线。

合并后本地复验使用隔离临时 PostgreSQL 与合成数据：服务端集成 **177/177**；相关真实 Fastify Playwright HTTP **18/18**；共享契约 **49/49**；共享适配器 **142/142**；全仓类型检查 **13/13**、`spec:check` **6/6**、`release:check` 和 `git diff --check` 均通过。`release:check` 仅验证版本记录结构，仍要求人工交付证据核对。设计草稿见 [配对流程 Figma 记录](../design/backend-auth-child-pairing-figma-2026-09-24.md)：iPhone 中文与 iPad 英文暗色画面已打开检查，属于原型而非运行中应用。没有原生配对、扫码、真机或生产服务验收，9.3b 与 SA-08 整体保持未完成。

## 后续增量：移动家长端只读接线

移动账号控制器现在以当前成人会话读取该家长实际监护的儿童列表，并在批准前预览服务端保存的配对设备描述。请求使用固定思玥 API 地址与 `expo/fetch`，会话切换会中止在途读取并拒绝迟到结果；受限 child 会话在本机直接被拒。控制器不把 access token、requestToken 或 pollSecret 写入可发布状态。

随后接入密码与 Apple 的家长再次验证批准入口。控制器仅批准同一会话刚预览过的配对，重新读取当前监护版本，拒绝额外字段、错误家庭标识和过期预览；授权 grant 不进入界面状态或本地保险库。共享适配器 **166/166**、移动端测试 **149/149**、服务端集成全量通过；真实 Fastify、临时 PostgreSQL 与 Playwright 的配对用例 **6/6**，其中新增密码路径从控制器经真实 HTTP 完成批准与儿童领取。全仓类型检查 **13/13**、`spec:check` **6/6**、`release:check`、`git diff --check` 通过。移动工厂测试使用受控模拟网络；Apple 原生授权、正式配对页面、扫码及真机均未验收。家长创建儿童的正式界面仍未接线，9.3b 与 SA-08 整体保持未完成。

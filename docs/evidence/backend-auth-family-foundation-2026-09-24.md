# SA-08 家庭身份仓储基础 · 2026-09-24

工作树：`feature/dev`，保留既有未提交改动。本批新增 `0009_family_core.sql`、家庭仓储、只接受已验证会话的 `GET/POST /v1/families` 和 `GET /v1/families/{id}`、严格共享摘要合同及回归。没有连接生产数据库、秋哥助手服务或真实家庭数据；未提交、推送、合并或部署。

成人须明确发起创建，不能靠注册账号自动获得家庭。服务端在主体锁下将家庭、owner 成员关系和按主体隔离的请求键记录原子提交；相同键重试返回同一家庭，不同键允许同一成人创建不同家庭。数据库约束同一家庭至多一个有效 owner。读取只返回当前主体 active 的家庭和成员关系；外部主体查询单个家庭返回与不存在相同的 404。响应只含家庭/owner ID、角色与版本，不含个人记录或白板授权。仓储的 `snapshot` 只从数据库装配现有 `familyPolicySnapshotSchema`；当前未建共享记录 grant，故 `record=null`、`grants=[]`，该快照不能给个人记录、图片或房间赋权。

验证：`corepack pnpm --filter @siyue/contracts test` 38/38；家庭仓储使用独立临时 PostgreSQL，包含 0008→0009 升级、运行角色无 TRUNCATE 权限、成人/儿童/停用拒绝、同键/异键并发、跨主体读取、角色及版本分离、可信快照，共 11/11。`corepack pnpm exec playwright test tests/e2e/families.spec.mjs` 使用真实 Fastify 和临时 PostgreSQL，2/2，覆盖明确创建、同键恢复、伪造角色拒绝、外国主体 404、无有效会话拒绝及并发同键。

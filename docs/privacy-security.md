# 隐私与安全基线

## 1. 数据用途分开授权

“保存在本机”“同步到某服务器”“发送给某模型/语音服务”“用于后台复盘”是不同授权。用户提供 API Key 不代表同意发送所有个人数据。

建议按模块和用途授权，资产、日记与录音默认更严格。跨域总结默认先展示数据范围和服务接收方。Apple 审核规则要求对个人数据向第三方 AI 的分享进行明确披露并获取许可；发布前还应复核最新规则。[S11]

## 2. 信任边界

模型、提示词、外部文件、网页和 MCP 返回内容都不是权限来源。工具执行器在代码层检查身份、权限、参数、版本、风险和审批。应用层同样保护读工具，不能只防写入。

首版禁用任意 SQL、Shell、无范围文件读取和任意 URL 服务端抓取。后续开放 BYOK 自定义端点时区分个人本机模式和多用户云端模式；云端需阻断内网、元数据地址及重定向绕过等请求风险。

## 3. 密钥

移动个人 BYOK 基础实现使用 Expo SecureStore 保存绑定地址的版本化配置；iOS 模拟器读写、重启和移除已验证，真机及本轮 Android 原生验证仍待完成，见 [验证记录](evidence/mobile-ai-settings.md)。它适合敏感小型键值，不能当作用户长期数据的唯一备份。[S12]

Electron 使用受保护的系统存储适配；实际系统不具备合适保护时不得默默降级为明文。平台模型密钥永不下发客户端。个人 BYOK 在哪台机器解密、被哪个服务使用必须可见。

禁止密钥进入 Git、日志、聊天消息、分析埋点、错误追踪或导出。删除 Key 不等于供应商侧撤销，用户应能区分本地移除与上游作废。

## 4. 审批与执行

审批绑定用户、space、runId、操作集合、payloadHash、baseVersion、有效期。执行前再次检查。默认只批准本次明确操作，不生成永久全域授权。

拒绝、过期、撤销和设备不支持都不产生正式写入。执行结果未知时按命令日志对账，不自动再执行。财务、导出、外发和批量删除按更高风险级别处理。

## 5. 删除与数据生命周期

删除须传播至正文、附件、缓存、摘要、检索索引及后续向量。备份有明确保留和过期政策，并记录恢复时的删除重放机制。不能承诺已经发给外部服务的数据可被本机立即彻底删除。

用户可单独删除错误记忆、清除对话或导出自己的数据。若提供创建账号，发布前完成账号删除流程，而不仅是退出登录。[S11]

日志默认记录脱敏元数据与错误码；调试内容记录必须显式、短期、可删除，不默认上传整段日记或录音。

## 6. 加密的边界

本地数据库加密、操作系统磁盘保护、传输加密和端到端加密是不同能力。文档和营销文案必须对应实际实现。

服务器无法获取解密密钥时，不能直接对密文做普通云端检索或后台总结。首版不宣称零知识和端到端加密已完成；后续设计必须同时处理恢复密钥、设备撤销与 AI 外发选择。

## 7. 上线与商业化前的门槛

完成目标市场、账号主体、隐私披露、数据保存/跨境要求、AI 服务可用性、模型许可与应用分发审核。资产域、未成年人、健康和监管服务另行扩大审查，不作“一次通过、全球通用”的保证。

数字订阅、第三方登录和动态代码扩展受平台规则约束，实施时核验具体条款。本文是工程风险清单，不是法律意见，也不证明已获得任何备案、许可或商标授权。[S11]

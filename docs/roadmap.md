# 里程碑与交付顺序

按验收推进，不以未知的个人投入时间编造工期。版本号是规划目标，不是已发布记录。

| 里程碑 | 目标 | 出口条件 |
|---|---|---|
| M0 立项基线 | 产品、架构、待决事项、工作包和验收定义 | 文档相互一致；未实施内容清晰标注 |
| M1 技术与最小闭环 | 三端骨架、存储/同步 PoC、AI 草稿到正式对象 | iOS 自然语言建目标并确认；重启仍在；重复提交不重复；Android/Electron 最小入口可验证 |
| M2 成长 Alpha | 语言练习、学习记录、基础记忆、用户触发复盘 | 完成目标—练习—记录—复盘；文字替代可用；来源可纠正和删除 |
| M3 多端可靠性 | 可选账号与同步、升级恢复、隐私和回归测试 | 冲突不静默覆盖；账号隔离；删除不复活；三端核心契约一致 |
| M4 开源 Alpha 发布 | 许可证与依赖审查、复现安装、发布资料 | 维护者确认许可与公开边界；没有真实隐私或密钥；发布说明与测试证据相符 |
| M5 扩展 | 手工资产；可选托管、后台任务与商业权益 | 独立验收，成本与目标市场审查后开放 |

## M1 的执行重点

先建立版本记录和共享包边界，再做真实存储与同步候选验证；同时以 Mock Provider 定义确定性的 AI 工具契约。真实 Provider 网络能力另行测试，避免将模型波动混入基础业务测试。

第一次演示只需证明：目标能变成已确认的正式记录，退出后不丢、重复后不多、拒绝后不写。不要先构造大量学习/资产/插件占位页面。

## 平台推进

iOS 是主产品节奏。Android 每条核心功能均有最低验收。Electron 早建运行与边界验证入口，成熟界面可稍后丰富；不改用 Tauri。桌面正式发布至少覆盖维护者决定的 macOS/Windows 目标，Linux 后置。

模拟器、编译成功与真机通过分开记录。不因当前环境无法进行 iOS 构建而把该项写成通过。

## 发布与回退

公开发布不等于商业上线。Alpha 先说明已实现范围与已知问题；同步尚未过 M3 的包只能作为单设备实验发布，不承诺多端可用。

破坏性数据迁移、公开仓库、付费服务和生产部署均需维护者明确批准。每个发布工件记录版本、来源 commit、构建平台和实际验证范围；应用更新不覆盖个人数据。

# 开源与商业化边界

## 1. 方向

用户已确认先个人开源、再逐步商业化。建议围绕同一核心，分别提供本地使用、自托管及可选托管服务，不复制成无法维护的两套业务代码。

可商业化的候选价值是托管同步、模型使用、备份与后台服务；不通过阻止导出或限制用户读取已创建数据强迫续费。定价、套餐和收费开始日期尚未确定。

## 2. 许可证

Apache-2.0 是讨论中的候选，不是已批准的许可证。本包不生成有效 LICENSE，也不声称已经开源发布。维护者需在首次公开分发前选择并记录许可及贡献接收方式。

不要把“未来商业化”理解为可以自动收回已授权版本的权利。具体许可条款、贡献者权利与商标政策由维护者审查，不在立项阶段代签法律声明。

同步、模型、UI、语音和复制来的代码逐项登记来源。PowerSync 官方将客户端开源包与 FSL 服务端/CLI 区分，因此不能把选用该服务描述为所有组件都采用同一 OSI 开源许可。[S10]

## 3. 旧项目复用

qiuge-helper 的纯 TypeScript 协议、审批思路、流事件和工具边界可作为设计参考；实际拷贝前需要检查源文件许可、依赖、业务耦合和隐私信息。不要整库复制账户、订阅、制造业务、生产域名或数据。

本次只进行架构级参考，没有把旧项目私有源码加入文档包。`qiuge-browser-use`、`mixuapp` 或 Hermes 的具体移植清单不是已执行任务。

## 4. 商业服务

未来使用 Entitlement 接口表达功能、额度、有效期和权益来源，不在页面到处写 isPro。平台模型密钥只在服务端使用。服务端计费与客户端展示分开，未知模型用量不记为零。

本地/自托管能运行不代表没有运维费用；BYOK 能调用不代表模型使用免费。公开托管服务在认证、限流、预算与滥用防护完成前不可开放。

## 5. 发布前检查

检查名称/域名/包标识权属、依赖许可和公告、真实数据与秘密扫描、隐私与第三方 AI 授权、数据删除、目标市场准入、签名与更新。Apple 数字订阅等规则需按实际商业模式复核。[S11]

这些检查作为待完成工作，不声明已经注册 Siyue 商标、拿到域名或满足所有地区要求。

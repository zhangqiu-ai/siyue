# 思玥统一原型

[siyue-prototype.html](siyue-prototype.html) 是项目唯一的界面原型文件，直接用浏览器打开即可点击操作。2026-09-25 起，所有新功能和新流程的界面设计都在这个文件里完成，不再使用 Figma，也不另建分散的原型文件。

## 流程

1. 需要改变行为、数据、权限或契约时，先按 [OpenSpec 流程](../../../openspec/README.md) 写清规格。纯界面调整可以跳过这一步。
2. 在原型中新增或修改对应页面和状态，把主路径做成可点击，并覆盖适用的加载、空、错误、结果未确认等状态。原型使用合成数据。
3. 维护者在原型中确认结构、交互和视觉后，才开始写正式代码。已有方向内的 S 级小改动不需要先改原型。
4. 正式实现与原型保持一致。实现时如需偏离原型，先更新原型并说明原因。

原型不代表功能已经实现或验收完成。正式验收仍按 [UI 验收](../ui-acceptance.md) 与 [测试策略](../../testing.md) 执行。

## 命名与文件约定

每个功能有一个小写英文功能 ID（如 `account`），三处保持一致：

| 位置 | 约定 | 示例 |
|---|---|---|
| 页面 ID | `<功能 ID>.<页面>`，页面部分用 camelCase | `account.login`、`account.delProgress` |
| 功能注册 | 在 `FEATURES` 中登记功能名称（中英）、设计说明文件、功能原则、异常场景和页面分组 | `{id:'account', groups:[…]}` |
| 设计说明 | 本目录下 `<功能 ID>.md`，写问题、信息结构、页面规格、接口依赖和待决项 | [account.md](account.md) |

新增功能的步骤：

1. 在 `SCREENS` 中加入 `<功能 ID>.*` 页面，每页写清 `label`（中英）、`notes`（2–4 条设计要点）和 `render`。
2. 在 `FEATURES` 中登记该功能，页面按用户任务分组；左侧跳转面板、设计要点面板和场景列表会自动生成。页面没有登记或 ID 重复时，浏览器控制台会报错。
3. 视觉只使用文件顶部与 `apps/mobile/src/ui/theme.ts` 同名的 Sage 语义变量，并复用已有组件函数（`row`、`btn`、`field`、`banner`、`steps`、底部表单等）。需要新变量或新组件时先在原型里定义并说明，确认后再同步到正式代码。
4. 依赖尚不存在的接口时，用 `anno()` 标出。
5. 右侧 Tweaks 必须能切换 iPhone / iPad、明色 / 暗色、中文 / 英文，以及该功能的异常场景。

可以用任何设计技能或工具产出，结果一律写回这个文件；版本历史由 Git 保留，不另存副本。

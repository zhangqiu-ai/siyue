# 账号

功能 ID：`account` | 设计日期：2026-09-25 | 状态：维护者已认可原型，正式 UI 尚未实施 | 原型：[siyue-prototype.html](siyue-prototype.html)（左侧跳转面板“账号”分组）

本方案重新设计移动端全部账号相关页面：登录、注册、找回密码、账号首页、登录方式、修改密码、登录设备、家庭责任、数据空间、注销及注销进度。视觉沿用已确认的 Sage 明暗主题，交互与信息结构整体重做。原型用合成数据演示；接口、行为语义和安全约束以现有 adapters/contracts 为准，本方案不改动它们。

## 1. 现状问题

证据来自 apps/mobile/src/screens/account-screen.tsx、registration-view.tsx、family-responsibilities.tsx 与 2026-09-25 的 iPhone 截图。

| 问题 | 表现 | 影响 |
|---|---|---|
| 一页塞下所有功能 | 登录、注册、找回、改密、设备、注销、家庭责任都在同一个组件里，按状态条件渲染 | 页面没有主线，用户找不到入口，也看不出自己在哪一步 |
| 低频操作占据首屏 | 修改密码的 3 个空输入框常驻在账号页顶部 | 最显眼的位置被最少用的功能占掉 |
| 没有身份信息 | 登录后只有一行“已登录”文字 | 用户不知道当前是哪个账号、用什么方式登录 |
| 所有区块同一权重 | 统一采用“粗标题＋说明段落＋全宽描边按钮”，“注销账号”和“管理登录设备”外观相同 | 危险操作不突出，页面也没有层次 |
| 验证时机错误 | 必须先点“管理登录设备”，再预先填好密码才能操作设备 | 多一步操作，而且在还不知道要做什么时就要求输入密码 |
| 说明文字过重 | 例如“撤销其他设备需要输入当前邮箱密码重新验证；若仅使用 Apple 登录，目前无法验证此操作。” | 把技术限制摊给所有用户读 |
| 状态离操作太远 | notice/error 统一显示在页面顶部 | 滚到下方操作时看不到结果 |
| 禁用态像坏掉 | 主按钮禁用时透明度直接降到 0.5 | 看起来像故障，而不是“还没填完” |
| 组件粗糙 | 家庭责任的复选框是 ☑/☐ 文字，家庭名称显示为截断的 ID | 不像正式产品 |

## 2. 设计原则

1. **一屏一件事。** 每个任务独立成页或成为一个步骤，主操作固定在底部拇指区。
2. **先身份，后操作。** 账号首页先告诉用户“你是谁、用什么登录、状态如何”。
3. **按需验证。** 只在执行敏感操作时，用底部表单要求输入密码，验证作用于这一次操作。
4. **视觉跟随风险。** 可逆操作用主色或中性色，只有不可逆的最后一步使用红色实心按钮；危险入口用红色文字，并与其他操作分组隔开。
5. **状态就近显示。** 字段错误显示在字段下方，“结果未确认”显示在对应操作旁，成功用短暂的 toast 提示。
6. **说清后果，不写教程。** 只保留影响决定的一句话，例如“修改后，所有设备都会退出登录，包括这台”。

## 4. 页面规格

**登录入口。** 大标题“登录账号”，下方一句用途说明和一行安心提示（锁图标＋“这台设备上已有的内容保持原样，登录不会上传”）。底部依次是“通过 Apple 登录”（系统样式按钮）、“使用邮箱登录”（色调按钮）和文字链接“还没有账号？创建账号”。存在注销回执时，顶部出现可点的横幅“注销请求处理中”。

**邮箱登录。** 两个字段：邮箱、密码。“忘记密码？”放在密码标签的右侧。错误显示在对应字段下方，输入内容保留。遇到限流时，主按钮直接显示倒计时（“28 秒后可重试”）。

**注册（3 步）。** 第 1 步：邮箱，加上一整行可点的同意复选框，条款链接嵌在句子里。第 2 步：6 格验证码（单个输入框叠加 6 个格子，支持系统自动填充），输满后自动进入下一步；“修改邮箱”就是返回上一步；重发按钮带倒计时。第 3 步：设置密码。规则为 6–20 个字符、不限字符类型（2026-09-25 维护者决定），用进度条和清单实时打勾，长度不足或超出时显示差几个字符，密码可显示或隐藏。现有接口在最后一次 confirm 调用中同时校验验证码和密码，因此第 3 步提交时如果返回 challenge_invalid，要回到第 2 步并保留已输入的密码。

**找回密码（2 步）。** 流程同注册。文案不透露邮箱是否已注册。完成页只有一个按钮“去登录”，并预填邮箱。

**账号首页。** 身份卡使用 focus 色：头像取打码邮箱首字母，只用 Apple 登录时显示人形图标；卡上显示打码邮箱，以及“已登录／离线”和登录方式标签。下面分三组列表：登录与安全（登录方式、密码、登录设备 N 台）、家庭（家庭责任，有待办时显示徽标）、这台设备（数据空间）。最底部是“退出登录”，单独一组；再往下是红色文字“注销账号”，也单独一组。离线时顶部显示警示横幅和“重试”按钮，需要联网的行置灰，行尾显示“需联网”。

**登录方式。** 基于已有的 loginMethods() 和 unlinkIdentity()。只剩一种登录方式时，标注“唯一方式”，不能移除。

**修改密码。** 独立页面。开头用信息横幅说明后果：“修改后，所有设备都会退出登录，包括这台”。三个字段都可以显示密码；“忘记了？”链接进入找回流程。结果未确认时，横幅改为警示样式，字段锁定，按钮变为“重试本次操作”，并且沿用原来的幂等键。成功后进入结果页，唯一的按钮是“重新登录”。

**登录设备。** 进入页面即加载列表。每一行显示平台图标、设备名（没有名称时显示“未命名设备”）和“最近活跃 · 登录方式”；当前设备标“本机”，其他设备行尾有“退出”按钮。点“退出”时从底部弹出验证表单：“退出「客厅 iPad」”，输入当前密码后执行“验证并退出”。只用 Apple 登录的账号，表单改为说明“暂时无法在这里退出”，并提示可以在那台设备上直接退出。列表底部是红色文字行“退出所有设备（包括这台）”，同样经过底部表单确认。结果未确认时显示横幅，引导先刷新列表核实。

**家庭责任。** 待确认的事项直接显示为任务卡，内容是“家庭名 · 谁请你接手 · 涉及几名儿童”，不再需要先点按钮加载。确认页用两个数字卡说明责任范围，加一句后果说明，再加两个真正的复选框控件，两项都勾选后才能确认。

**数据空间。** 用两张说明卡介绍“原本机空间”和“账号空间”，标出当前使用的是哪一个；按钮“创建账号空间”，并注明原内容不会移动，也不会上传。

**注销。** 采用全屏模态，顶部显示三段进度。第 1 步：用三行图标说明影响，主按钮用中性色。第 2 步：每个家庭一张卡片，单选且不预设默认值；选择“转交管理”后，卡片里出现“选择接收人”；底部显示“已处理 x/y”。接收人页中，尚未接受的成员不能选，并写明原因。第 3 步：先汇总所有选择并提供“修改”入口，再进行身份验证（密码或 Apple），最后是红色实心按钮“注销账号”。进度页用时间线分别显示各项状态，并明确说明回执失效不代表删除已经完成。

## 5. 组件与 token

新增共享组件，放在 apps/mobile/src/ui/：TextField、PasswordField（带显示/隐藏）、OtpField、PasswordRules、Button（primary / tonal / text / danger / dangerFill / apple，内置 loading 状态）、Banner（info / warn / error，可带操作按钮）、ListGroup、ListRow（图标块、值、徽标、尾部控件）、ChoiceCard、Checkbox、StepHeader、BottomSheet（验证表单）、Toast、ResultView。

| 规格 | 取值 |
|---|---|
| 大标题 | 30/38 semibold；页面顶部只放大标题，导航栏只保留 44pt 圆形返回按钮 |
| 正文 / 行标题 | 16–17；辅助文字 13–14；一屏不超过 3 个字号层级 |
| 圆角 | 分组与卡片 20，输入框与按钮 16，小按钮 12，身份卡 24 |
| 触控 | 行高 ≥56；按钮高 52；图标按钮 44×44（Android 48） |
| 输入框 | surface 背景＋1.5 border；聚焦时用 accent 边框加外发光；错误时用 error 边框 |
| 禁用 | 用 subtle 背景＋muted 文字表达，不用整体透明度 |
| 动效 | push 约 340ms、模态上滑约 380ms、按压缩放 0.985；开启“减少动态效果”时关闭 |

在 theme.ts 中新增 4 个语义 token，明暗两套分别配对：errorSurface、warn、warnSurface、以及 apple/onApple（Apple 按钮在明色下为黑底，暗色下为白底）。它们需要通过现有的 theme-contrast 测试，并同步到 Figma 变量。

## 6. 状态映射

| 认证状态 | 页面表现 |
|---|---|
| bootstrapping | 身份卡骨架屏（不显示纯文字“正在恢复登录…”） |
| anonymous | 登录入口 |
| authenticating / 请求中 | 按钮内显示 loading；usePreventRemove 阻止离开，并弹出原有的提示 |
| authenticated | 账号首页 |
| 离线（有账号但无法验证） | 首页顶部警示横幅，需要联网的行置灰 |
| reauth-required | 登录入口顶部横幅“登录已失效”，预填邮箱 |
| secure-storage-unavailable | 全页错误结果视图：说明原因，按钮“重试”，并注明“原有内容已保留” |
| passwordChangePending | 修改密码页进入锁定重试状态 |
| 回执存在且未登录 | 登录入口顶部显示注销进度横幅 |

需要保留的现有行为：幂等键与“重试同一请求”、账号主体变化时清空表单、注销进度只能从本机回执读取、只能打开 HTTPS 条款链接、验证码与密码不进入可观察状态。

## 7. iPad、双语与无障碍

- iPad 横屏及宽窗口采用双栏：左侧是 380pt 宽的账号首页，常驻显示并高亮当前选中的行；右侧是详情，内容最宽 560pt。未登录页面居中显示，列宽 440pt。注销流程在 iPad 上用 formSheet 打开（560×740）。窄窗口和竖屏分屏时回到单栏 push。具体断点在实施时按实际可用宽度确定。
- 英文文案按“短动词＋对象”重写，原型可以切换语言检查长度。所有按钮允许换行；大字号（AX3）时，行尾的值移到标题下方。
- 纯图标按钮提供无障碍名称；OtpField 对外只暴露一个输入框；错误使用 alert 角色，状态变化使用 polite 播报；颜色之外一律配合文字或图标表达状态。

## 8. 重构方案

1. **P1 基础组件与已登录页面。** 新增 token 和组件，拆出账号首页、登录方式、修改密码、登录设备，把 account-screen.tsx 中对应的状态抽到 hooks（usePasswordChange、useDeviceSessions）。
2. **P2 未登录流程。** 登录入口、邮箱登录、找回和注册拆成独立路由，继续复用 createEmailEntry 和 createEmailRegistration，不修改它们的状态机。
3. **P3 注销、家庭责任与数据空间。** deletion-screen.tsx 按步骤拆成路由；family-responsibilities.tsx 按新样式重写。
4. 每一期同步更新双语文案，以及 apps/mobile/e2e/account-auth 下的原生/Android 脚本和定位器，并按 docs/design/ui-acceptance.md 的 L 级完成验收：中文/英文 × iPhone/iPad × 明色/暗色，以及大字号和键盘路径。

## 9. 接口依赖与待决项

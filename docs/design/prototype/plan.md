# 计划创建

功能 ID：`plan` | 设计日期：2026-09-25 | 状态：维护者 2026-09-25 确认原型，正式 UI 尚未实施 | 原型：[siyue-prototype.html](siyue-prototype.html)（跳转面板“计划创建”）

## 现状问题

草稿页上同时堆着五种状态提示和六七个按钮。只要有未保存的修改，“确认保存计划”按钮就直接消失，用户找不到下一步。手工填写要跨两屏，而且初始没有任务。理由只能看不能改。确认成功后停在原地，只能手动返回。日期字段在契约里存在，但界面没有入口。

## 页面

- **写下目标**：一个大输入框，上方用分段控件切换“AI 帮我拆解”和“自己填写”，两条路进入同一个草稿页。下面有三个一点就能填入的示例、一句发送范围说明（“只发送这段目标文字”），还能选择要加入哪个空间。
- **生成中**：用骨架屏预告草稿的样子，同时引用你刚写的目标；随时可以停止，停止后不留草稿。
- **计划草稿**：只有一页。标题、目标日期、要加入的空间、“为什么这样拆”、项目名、任务列表都可以直接修改。任务可以拖动排序、删除，最后一行添加新任务。修改自动保存到草稿，顶部显示“草稿 · 自动保存 · 28 分钟内有效”。底部固定两个按钮：“加入「空间名」”和“放弃草稿”（放弃前会确认）。
- **已加入**：说明加入了什么（1 个目标、1 个项目、N 项任务），并提示今天的任务已经出现在空间首页；按钮是“查看目标”和“完成”。

## 状态

| 场景 | 表现 |
|---|---|
| 未连接 AI | “AI 帮我拆解”不可用并说明原因，默认切到“自己填写” |
| 草稿过期 | 顶部说明内容还在，唯一的按钮是“用这些内容重新创建” |
| 结果未确认 | 标题锁定，唯一的按钮是“核对保存结果”，避免重复加入 |

## 依赖与待决

- 草稿契约 `GoalDraft` 没有日期字段，需要扩展后才能在草稿阶段设置目标日期。
- “编辑自动保存”要把 `editDraft` 改为防抖自动提交。确认时如果草稿版本已经变化，先保存再审批，审批仍然绑定当时可见的内容和版本。
- 计划可以从空间页、对话里的草稿卡和空间首页的草稿提示三处进入，三处打开的是同一个草稿页。

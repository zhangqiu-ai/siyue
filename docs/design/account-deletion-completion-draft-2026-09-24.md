# 注销流程补全草案

状态：2026-09-24 维护者明确采纳推荐规则与设计稿，授权实施和本地验证；不授权操作真实生产数据。关联 add-shared-api-independent-auth。

## 已确认

逐个家庭选择；转交只允许该家庭有效成人且本人明确接受管理及适用监护责任；唯一管理者结束管理且仍有他人时冻结，撤销儿童设备授权，共同作品保留待核对。

## 已采纳的具体方案

1. 冻结家庭由指定运营人员复核处理。不能由普通成员自行解冻。恢复须核对现有有效成人接收人的明确接受、儿童适用监护责任及共同作品处置记录；未满足条件继续冻结。处理操作必须有理由、幂等键及审计，不能更改他人的作品归属或静默恢复旧儿童设备授权。
2. 注销历史清理采用分层规则：本人失效凭据、临时邀请和配对材料清理；涉及其他成员的有效关系与原始作品不连带删除；已结束的历史关联仅在不损伤他人权益、重放保护和必要审计时去除注销者身份关联。本人独立内容删除；共同作品中本人贡献不可安全区分时转人工核对，未处理完不报告服务端数据全部已删。新增保留期限另行明确，不能凭空设定无限保留或自动销毁日期。

## 页面顺序

账号与安全 → 注销影响 → 逐家庭选择 → 再次验证与最终确认 → 已受理／进度。

- 影响页：本人资料、家庭及儿童设备的真实影响；本机与服务端删除分开说明。
- 家庭页：每个家庭明确选择；转交展示有效成人及接受状态，无接受记录不能提交；结束管理显示冻结或结束本人访问后果。
- 确认页：密码或 Apple 再验证；二次确认；提交结果未知时锁定原选择并提供原请求重试。
- 进度页：服务端资料清理、家庭待核对、Apple 撤销分别显示；回执失效不显示完成；不展示回执密钥。
- 冻结页：只显示本人仍可知的冻结状态及核对进度，不开放旧共享权限或默认提升角色。

覆盖 iPhone、iPad、桌面和中英文；Figma 交互草稿已获维护者采纳，继续实施新流程 UI。

## 实施补充 · 2026-09-25

候选成人及其明确接受状态改为真实 API 读取；家庭按编号区分，候选人使用家庭内可见显示名或主体编号，不虚构成员姓名。接收人在本人账号的“家庭责任”入口先看范围，再分别确认管理和适用监护责任。冻结家庭的接受只进入运营复核，不开放旧权限。运营入口采用独立数据库登录身份的 CLI，普通客户端没有复核或解冻接口。桌面暂不具备原生 Apple 再验证能力，Apple-only 用户仍需移动 iOS 入口；页面明确说明能力边界。

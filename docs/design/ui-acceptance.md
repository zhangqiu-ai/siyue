# UI 设计与验收标准

版本：2026-09-07。适用：思玥现有及后续移动、桌面界面。方向以 [DESIGN.md](../../DESIGN.md) 为准；本文规定怎么检查、何时算完成，不替代业务验收或 OpenSpec 功能规格。

状态：维护者已授权建立详细规则。以下数值是项目实施基线，不是所有页面已达标的证明，也不是全部来自平台强制标准。现有页面按后续涉及范围逐项校正，不因此自动开启全仓重构。

## 1. 产品感的判断方式

| 目标 | 必须能回答的问题 | 不通过的典型表现 |
| --- | --- | --- |
| 简洁 | 首屏最重要的内容或操作是什么？删除某元素会损失什么？ | 口号、品牌、分类标题反复出现；用说明填空白；多个同权重主按钮 |
| 整齐 | 同类元素是否使用同一对齐线、尺寸和间距？ | 行内文字忽高忽低；图标视觉大小不同；同级卡片各用不同圆角 |
| 优雅 | 操作前后是否自然、稳定、可预期？ | 键盘挡住输入；加载使按钮跳位；弹层退出丢输入；流式输出强拉滚动 |
| 美观 | 字体、留白、色阶和强调是否形成一致层次？ | 字号过多；粗体到处都是；装饰比内容醒目；只有浅灰边线能识别输入框 |

审美不是一个可由测试自动证明的分数。硬性检查排除缺陷，视觉审查判断整体；不要用“90 分”或“所有尺寸都是 8 的倍数”代替真实审查。

## 2. 尺寸与排版基线

单位：iOS 使用逻辑 pt，Android 布局用 dp、字体用 sp，Web 使用 CSS px；React Native 使用逻辑尺寸。不要把截图的物理像素直接当作布局单位。原生控件优先遵循平台尺寸，文字放大时不强行固定高度。

| 项目 | 默认基线 | 验收方法与允许变化 |
| --- | --- | --- |
| 间距 | 4、8、12、16、24、32；4 为细调，8 为常用步长 | 相同语义使用相同间距；分组间距大于组内间距；系统 safe area 不受倍数限制 |
| 页面边距 | 手机默认 20；紧凑宽度可用 16；桌面 24–32 | 同页同层级统一；标题、列表和输入起始线一致；改值必须是整页规则 |
| 列表与卡片内距 | 默认 16；紧凑区域 12 | 不因文字长短改变左右内距；尾部箭头和状态有统一对齐线 |
| 圆角 | 输入/小控件 12，独立内容容器 24，圆形按钮/胶囊按形状定义 | 同一种组件只用一个样式；避免每个局部随意选 10/14/18/20；平台原生样式与已批准组件可例外 |
| 正文/输入 | 16–17，常规字重 | 中文默认行高约字号的 1.45–1.6 倍；以字形不裁切和阅读节奏为准 |
| 页面重点标题 | 24–28，中等或半粗 | 只在确有层次需要时出现；系统导航标题使用系统样式 |
| 次级标签 | 14–15；辅助信息 12–13 | 必要决策、错误与恢复信息不能靠极小字号弱化；正文不能降成辅助字号 |
| 字重和层级 | 常规、medium、semibold；一屏通常不超过 3 个字号层级 | 层级数量是检查信号，不机械限制消息富文本或无障碍字号 |
| 通用图标 | 20–24；统一图标家族、线宽与视觉重量 | 相同作用同图标；设置齿轮、新建对话撰写、关闭叉号、返回箭头 |
| 触控范围 | iOS ≥44×44；Android ≥48×48；共用组件可统一 48×48 | 图形可小于点击范围；扩展热区不能被父层裁切或与邻项重叠 |
| 行与按钮高度 | 普通列表默认 56；文字按钮 48；多行按内容增长 | 不能为了整齐裁切文字；同组一行内容的基线/高度一致 |
| 桌面内容 | 正文建议约 60–80 个字符宽，宽屏不无限拉长 | 面板可更宽；表格、代码按内容处理；最小支持窗口下无页面级横向溢出 |

`apps/mobile/src/ui/theme.ts` 已有 8/16/24/32 间距及 24/12 圆角；本文不声称排版和图标 token 已实现。新增组件先复用现有 token，确需扩充时统一命名并验证受影响页面。局部光学修正允许，但需说明原因，不以此任意覆盖组件规则。

## 3. 视觉与内容检查项

每项填写 pass / fail / not_run / n/a；n/a 必须解释。数字基线的偏离不是自动失败，但必须有明确用途及一致的组件规则。

| ID | 检查与通过条件 |
| --- | --- |
| UI-V01 焦点 | 一屏只突出当前主任务；设置、帮助等低频入口不抢占主内容。无必要主动作时不硬放主按钮。 |
| UI-V02 文案 | 品牌只在移动侧栏顶部；无重复页名、口号或上下文已经说明的标题。默认说明删减或就近展开；费用、外发范围、删除后果和恢复办法仍可找到。 |
| UI-V03 对齐 | 同级元素左/右边缘与文本基线一致；图标在热区内视觉居中。用布局/浏览器边界检查，截图检查视觉偏移。 |
| UI-V04 节奏 | 同类间距与圆角一致，组内近、组间远；空状态留白有主次，不能靠 spacer 固定高度把内容推到屏外。 |
| UI-V05 字体 | 使用系统字体；中文、英文、数字混排无裁切、异常行距或对齐跳动；不要禁用系统文字缩放来让截图好看。 |
| UI-V06 图标 | 通用操作优先图标，含义模糊则用短标签；生产控件优先平台符号或统一矢量图标，不混用 Emoji、随字体变化的 Unicode 图形和不同风格图标。已有字形图标属于待统一项，不能因此宣称已符合图标规范。 |
| UI-V07 色彩 | 黑白灰、仅明暗主题；语义色成对使用，两种主题分别检查文字、禁用、分隔、选中、输入及弹层。不靠颜色单独说明状态。 |
| UI-V08 对比度 | 项目采用正文、标签及有意义的提示文字至少 4.5:1；识别控件/状态所必需的非文字图形至少 3:1。纯装饰分隔线可更低；不可用装饰边线替代必要的输入边界。禁用控件按标准可豁免对比度，但须能理解禁用原因。用实际前景/背景计算，不能凭截图感觉判断。 |
| UI-V09 内容压力 | 空、1 项、20 项列表；标题 2 倍长度、中英混排、长模型名/URL、长消息均无重叠。仅列表摘要可合理省略，完整内容有查看路径；编辑中的值不被省略成不可编辑。 |
| UI-V10 一致性 | 同功能跨页面的图标、标签、选中、禁用和点击反馈一致；平台导航保留平台习惯，不强求三端像素相同。 |

## 4. 交互与状态检查项

| ID | 检查与通过条件 |
| --- | --- |
| UI-I01 可操作 | 所有可点元素有反馈且命中正确动作；纯图标有准确名称、角色与选中/展开状态。不要留下无响应的假按钮。 |
| UI-I02 导航 | 返回、系统手势、侧栏、新建、弹层关闭各自语义明确；不叠出重复页面，不无故退出主任务。只有一个主页面时不造单项底部栏。 |
| UI-I03 输入 | 聚焦、输入、多行、粘贴、清空、键盘收起正常；键盘打开时当前输入与发送/保存动作可达，底部安全区不被覆盖。 |
| UI-I04 编辑保护 | 返回/关闭后如何处理未保存输入必须在功能规格写清。会造成不可恢复丢失时，保留草稿或提供明确舍弃选择；不能每次无修改返回也弹确认。 |
| UI-I05 加载 | 点击有即时按压/忙碌反馈，不等待网络才变化；异步期间防重复提交，主布局不突然跳动；等待可结束、可超时，长任务按功能支持取消。 |
| UI-I06 错误 | 用合成失败验证错误可理解、可恢复且保留有效输入；无原始堆栈/秘密。禁用不能替代错误解释；重试不造成重复重要写入。 |
| UI-I07 空/离线 | 空列表不等于加载失败；离线不清掉已有内容；未配置 AI 时无自动调用或伪造成功。提示在相关操作处出现，不恢复首页常驻设置引导。 |
| UI-I08 聊天流式 | 首字到达后增量展示；用户向上读历史时不强拉到底，回到底部有可发现入口；输入保持可用；停止保留已生成内容并明确结束状态，重试不静默覆盖用户输入。 |
| UI-I09 配置与危险动作 | 保存状态与实际保存一致；选供应商不等于已保存。删除、切换配置导致清空/停止等后果在操作前可见；失败不宣称成功。 |
| UI-I10 无障碍 | VoiceOver/TalkBack 阅读顺序合理、装饰不重复朗读、错误/运行状态不过度播报；桌面 Tab 可遍历、焦点可见、Escape 关闭适用弹层且焦点回到触发处。 |
| UI-I11 动效 | 优先平台动效；自定义微反馈以 150–250ms 为起点，不拖延输入或操作。尊重减少动态效果设置；键盘/流式/展开不闪烁，无反复无目的动画。时长是项目建议，不是平台硬指标。 |

并非每个页面需要所有状态。实施前列出适用的默认、空、加载、成功、失败、禁用、选中、离线、取消及未保存状态；明确如何触发，不凭想象勾选通过。

## 5. 验收分级：细节把控不等于重复劳动

| 级别 | 适用变化 | 必做证据 | 不强制的工作 |
| --- | --- | --- | --- |
| S 小改 | 不改变语义的文案、删重复标题、微小间距 | diff、相关静态检查；明确原预期与影响范围 | 不为此重做原型、截图或全仓测试 |
| M 页面/组件 | 新布局、图标替换、导航入口调整、多处样式、交互组件 | 受影响页面实际操作；适用状态；两种主题；至少目标设备实际截图并逐图查看；相关类型/组件或行为检查 | 不因改文案跑无关数据库测试 |
| L 新流程 | 新页面功能、导航/信息架构、复杂表单、聊天/数据/权限行为 | OpenSpec 标准流程；先低成本原型；关键路径与失败路径；跨端适用验证；独立审查与证据 | 不把浏览器原型截图当作原生完成 |

分级以实际风险为准：一句费用或删除文案如果改变授权语义，不能因为字数少就归 S。涉及字体长度、图标是否显示、布局重排的“小修改”有视觉不确定性时，补一张定向截图即可，不要求全套截图。

### 设备与场景矩阵

- 语言：中文与英文均为必需。M / L 级涉及文案或布局时，两种语言均检查受影响页面与适用状态；与 iPhone / iPad 矩阵交叉覆盖关键输入、导航、弹层及错误路径。记录实际 locale、设备与窗口，缺少语言覆盖标记 not_run。
- 检查语言资源键是否完整、页面是否出现原始键/缺失翻译或意外语言混杂；无障碍名称同步验证。用户原文和供应商/模型技术标识不属于待翻译文案。日期、数字、金额按已明确的地区策略验证，切换和回退仅按获批准规格测试。
- S 级文案修改也须同时更新受影响的中英资源并做完整性检查；长度变化可能影响布局时补定向截图，不要求每次跑全部设备/主题/语言组合。


- M / L 的移动页面或布局：iPhone 与 iPad 必须同时检查，明/暗覆盖受影响组件。iPhone 至少覆盖紧凑宽度（逻辑宽度 375 左右）和较宽手机（430 左右）；iPad 覆盖横屏、竖屏及当前支持的窄窗口/分屏宽度，并实际操作尺寸切换。记录设备、系统和实际可用逻辑尺寸，不把数字当型号，也不预设所有设备相同断点。
- iPad 内容宽度、导航、弹层和输入区依据可用空间组织，不能只将手机内容无限拉宽；是否分栏及具体断点在对应原型/规格确认。旋转、窗口缩放或键盘开关不能引发意外丢输入、重复提交或主操作不可达。
- iPad 相关文本输入同时检查屏幕键盘与外接键盘下的编辑/发送/焦点路径；缺设备时标记 not_run，不能拿 iPhone 或模拟器结果代替 iPad 真机验收。首次建立页面基线需两类设备的证据，后续 S 级修改仍按原有定向检查规则，不重复跑所有组合。
- 文本/表单相关：默认字号 + 一个较大辅助字号（例如 AX3，记录实际档位）；Web 文本缩放 200%。窄屏、大字时允许换行、增高和滚动，不允许必要操作不可达。
- 键盘相关：键盘开/关、多行及长输入；截图与操作都检查，不能只有键盘关闭的首屏。
- 共享组件或布局改动：Android 至少做适用的原生检查；环境未就绪写 not_run，iOS 通过不能代签 Android。
- 桌面：常用窗口与已支持的最小窗口、鼠标与键盘；本地网页无 IPC 只证明布局，正式业务须 Electron 验证。
- 截图用合成数据，避开 API key/私人会话；对比前后使用同设备、主题、字号和数据。不同条件时注明，仅作参考，不作像素对比。
- 原生权限、触控感受和性能敏感改动仍需真机；模拟器可作为迭代验证，不替代发布验收。仅截取受影响状态，不要求每次遍历所有组合。

## 6. 设计到交付的步骤

1. **明确任务**：用一句话说明用户目的；列范围、主操作和适用状态。先读已有组件与规则，不重新发明风格。
2. **确定结构**：L 级或明显改变方向时做低成本原型，让维护者确认信息结构与整体感觉；必要时给两个有真实取舍的方案，不机械做三套。M/S 已有方向内直接实施。
3. **实现**：复用组件/token；布局、文案、状态一起完成；不把后续错误处理作为默认欠账。
4. **自检**：按适用 UI-V/UI-I 编号逐项核查，记录缺陷并修复；涉及独立页面/状态时可并行审查，避免两个代理重复改同文件。
5. **验收**：按 S/M/L 获取证据；截图必须实际打开查看，指出结论与限制。复杂流程最好由未写该模块的审查者再过一次关键路径。
6. **交付**：给出简短结果、代表性图或链接、未验证项。维护者只需决定方向和审美取舍，不负责发现对齐、裁切、漏状态等基础问题。

本轮规则建立按 OpenSpec 简化路径处理（纯文档，无应用行为变化）；后续 L 级 UI 变更仍遵循 [现有 OpenSpec 流程](../../openspec/README.md)。不建立第二套提案目录，不把本文要求写成已经通过的现行产品行为。

## 7. 通过、阻断与例外

- **阻断**：主操作不可达、裁切导致信息/操作丢失、误触/重复重要写入、错误或结果虚假、焦点陷阱、密钥暴露、缺失重要后果提示。发现一项就不能宣称该流程验收通过；与业务/安全完成定义共同生效。
- **必须修正的视觉问题**：同组件明显不齐、图标混杂、重复标题抢焦点、必要文字对比不足、明暗主题漏色。适用项修正后才能标为 UI 完成；审美偏好争议由维护者决定，记录采用的规则。
- **可记录的小偏差**：不影响理解和操作的光学微调或平台原生差异，可附原因、范围和后续处理。不能把所有未测项写成“后续优化”。
- pass 必须有实际证据；fail 表示已观察到问题；not_run 表示未执行；blocked 表示外部条件阻塞；n/a 表示本次不适用。状态不能互换。
- “UI 已完成”须适用硬性项通过、视觉问题处理、有对应环境证据；未测平台只能交付已验证范围。规则落地不代表历史页面自动达标。

## 9. 依据与解释边界

核对日期：2026-09-07。通用无障碍底线参考 [Apple HIG Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility/)、[Android 触控范围](https://support.google.com/accessibility/android/answer/7101858?hl=en)、[WCAG 2.2](https://www.w3.org/TR/WCAG22/)（1.4.3、1.4.11、1.4.4、2.4.7 等）。WCAG 普通文字为 4.5:1，大字有 3:1 例外；本项目为减少判断歧义，默认有意义文字统一以 4.5:1 检查。平台建议与 Web 一致性标准不可混称为原生平台的强制合规结论。

间距、圆角、字体层级、动效时长和验收分级是思玥工程基线。采用它们是为了保持一致，不保证某套数值天然“高级”。现有主题 token、页面截图和测试需独立核对；当前未实施统一图标组件、完整字号与设备矩阵，不在本文虚构完成。

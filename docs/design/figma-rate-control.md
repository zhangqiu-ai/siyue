# Figma 调用节流与限流诊断

依据：维护者纠正及 [Figma 官方说明](https://developers.figma.com/docs/figma-mcp-server/rate-limits-access/)（2026-09-09 核对）。每日调用额度和每分钟速率限制同时存在；本项目按每天最多200次、每分钟最多10次的边界保守安排。官方说明部分工具豁免，但当前连接器各工具的具体计费归类未核实，不据此增加频率。

## 执行约束

- 只有主代理调用Figma；子代理只准备脚本和做本地检查，避免各自限速却合计超限。
- 所有Figma工具合并串行排队，调用开始时间至少间隔8秒，滚动60秒内最多8次，留出余量。
- 在本地准备代码、检查参数和输出大小后再调用；成功的读取复用结果，不以重复存在性检查代替实际验收。
- 记录每次开始/结束时间、工具、用途、成功/失败及服务返回的限流信息。会话计数只代表本次已记录调用，不代表账号当天总用量。
- 收到限流先暂停整个Figma队列；若返回Retry-After则遵守。未提供时至少冷却65秒，再进行一次有实际用途的只读复查。仍受限可进一步延长冷却，但不连续重试消耗额度。
- 只有明确的日配额字段、可核实的账号日用量或重置说明才支持“当天额度耗尽”。通用tool call limit、短期成功后再失败、跨轮重复出现均不足以区分日额度与分钟限制。
- 冷却后成功说明当时可用，支持短时限制的可能性，但不能单独证明之前只有分钟限制。冷却后失败也不能单独证明日额度已满；保留“限流原因未确定”。
- 不把跨三个对话轮次当成三个独立冷却窗口。受阻状态描述实际无法操作的事实，不推断套餐不足，不自动升级或购买。

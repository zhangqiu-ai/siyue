# 版本计划与功能归属

2026-09-07 维护者确认采用。本目录回答“这一版计划交付什么”，不重复功能规格和测试日志。当前开发版本由根 `package.json.version` 指定，计划文件与其同名；当前为 [0.0.2](0.0.2.md)，完成发布门槛后发布。

## 登记与状态

1. 开发前登记版本归属：标准变更在 proposal 中写唯一一行 `Target release: x.y.z`，并在对应计划中链接变更、工作包、状态和证据。简化修改也在版本计划登记，可合并同类小项，不为此强建 OpenSpec。
2. 每项使用“计划中 / 开发中 / 待验收 / 已验收 / 延后”。已有部分证据但关键验收未完成仍为待验收；已验收必须写明平台、语言、范围及证据。版本状态与工作包状态不同，不自动同步为 done。
3. `CHANGELOG.md` 面向用户，仅将满足本版约定验收范围的变化写入“新增 / 改进 / 修复”；未完成项留在计划。已知限制可提前记录，但不能用限制声明免除中文/英文或 iPhone/iPad 必需要求。
4. 延期保留原记录、原因和目标版本；去向未定写“待排期”，不擅自指定下一版本。目标未定时提案暂保留原 Target release 作为登记归属，原计划标明“延后 / 待排期 / 已移出本版交付”，不再视为本版发布项；确定新版本后再同步提案和新旧版本计划。已发布归属不改写，事实纠错需留说明。
5. 发布前核对本版范围、逐项证据、遗留阻断、应用版本和真实工件中的版本。未完成项须经维护者确定延后/缩减；明确必需约束不得自行降为可选。
6. 实际发布且取得发布结果后，计划标“已发布”，CHANGELOG 标真实日期并链接工件或发布记录；不能将 commit、tag、构建或上传尝试当作已发布。发布、推送等仍需当次授权。

## 版本配置

- 本阶段应用和私有共享包统一跟随根版本，移动 Expo 配置同步；后续如需独立包版本，另行决策。
- 文档版本、数据库 schemaVersion、API 协议版本及依赖版本不跟随产品版本替换。原 `0.1.0` 工程声明不构成已发布记录，历史测试证据保留原值。
- iOS build number、Android versionCode 是独立构建编号，发布前核验，不在本规则中重置。生成的原生工程需在实际构建时同步并检查包体版本；当前已安装旧 App 不因修改源码自动升级。
- 新功能必须先有归属；下一版本号由维护者决定。不要自动全仓替换版本字符串。

## 检查与文档职责

`corepack pnpm release:check` 检查工程版本一致、当前计划和日志入口、活动提案版本归属及登记；它不判断功能是否真的完成或工件已发布。与 `spec:check`、相关业务测试和人工发布审查配合。

根 AGENTS 是执行规则；PRODUCT 管产品范围；OpenSpec 管行为；backlog 管工作包；本目录管版本归属；docs/evidence 管证据；CHANGELOG 管用户可读的实际变化。同一事实用链接引用，勿复制多份需求。

提案模板使用 OpenSpec 内置模板，通过 config.yaml 的规则增加 Target release；无需全局工具更新。已有活动变更本次补归属，仅属计划整理，不替代原授权，也不批准扩大范围。

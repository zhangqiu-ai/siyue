## Why

已有严格会话边界和家庭权限内核，但缺少独立 PostgreSQL 身份仓储与生产会话。维护者要求依据已确认方案推进，并先保存三份原件到项目。

Target release: 0.0.1

## What Changes

保存并核对原始方案；首批按 SA-01～03 推进独立数据库、迁移、最小权限、健康检查、真实会话与刷新恢复。后续邮箱、Apple、客户端和家庭接线分别实施与验收。其中邮箱一项已由 2026-09-25 授权与当日实际公网验收替代：邮箱注册、密码登录、重启恢复与注销均已实施并验收。

## Capabilities

### New Capabilities

- `independent-auth-foundation`：独立数据库、受控迁移与生产会话基础。

### Modified Capabilities

无已归档业务规格变更。保留既有严格 session 合同；活动账号提案中的旧邮箱验证码直接登录方向由本次确认方案替代。

## Impact

后续实施涉及 apps/server、共享认证契约、依赖锁文件与测试。关联 SY-005 安全边界与 SY-022 身份依赖，不提升原工作包完成状态。白板、家庭权限及现有客户端数据保留。

## Authorization

2026-09-21 维护者要求依据「评估后端与微信登录」最后方案推进本地开发，并提供三份下载文档。原件入口为 [方案登记](../../../docs/architecture/backend-auth-v1/README.md)。本地编辑与隔离验证已授权；推送、合并、部署、购买、申请 AppID、生产迁移和第三方数据外发不在本次授权内。

2026-09-25 维护者追加授权：彻底打通注册页面 → 真实验证码邮件 → 公网注册 → 登录及重启恢复，并明确允许暂时共用 qiuge-helper 的发信服务。授权包含实现目标所需的思玥独立服务配置与部署；不包含购买、修改其他产品服务/数据、公开源码或向未指定第三方发送测试邮件。实际收件邮箱、正式协议/隐私正文及运营主体仍待取得，不能用占位同意发布注册。

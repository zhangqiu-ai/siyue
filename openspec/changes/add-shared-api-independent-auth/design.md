## Context

依据 [主设计](../../../docs/architecture/backend-auth-v1/Siyue_Backend_Auth_Design_v1.0.md)、[交接](../../../docs/architecture/backend-auth-v1/Siyue_Implementation_Handoff.md)、[验收表](../../../docs/architecture/backend-auth-v1/Siyue_Acceptance_Checklist.md)。原件保持不变，实际证据单独记录。

当前 feature/dev@fee1f4b 已含白板实现，开工时工作区干净；不回退到原文较旧的 feature/dev。现有 SessionVerifier、严格 VerifiedAccountSession、账号查询客户端与家庭领域策略继续复用。

## Goals / Non-Goals

首批按 SA-01～03 实现数据库和会话内核，为邮件与客户端提供接口。随后按原方案继续 SA-04～10；每批分别验证，不把首批通过当作整体完成。不改变白板、不自动上传本地内容、不操作秋哥助手服务。

## Decisions

- 采用 pg＋参数化 SQL 与版本迁移，不引入 ORM。事务使用同一连接，池与等待有界。
- 独立 provision 建库与 owner/migrator/app 角色；迁移校验库、角色、环境，取得锁并记账 checksum；API 不自动迁移或持有管理员凭据。
- 使用成熟 JOSE 库及独立 ES256、issuer/audience/kid/token_use。每次验证数据库会话、主体与 credential_version，不把家庭权限放入 JWT。
- 刷新事务创建唯一后继；旧凭据存摘要，同 rotationId 在 60 秒内仅恢复原加密响应，且后继尚未消费；不同请求重放须实际提交设备链撤销，不随错误回滚。
- reauth 为五分钟、一次性、动作绑定的证明；消费与受保护动作同事务。没有真实凭据验证时不提供公开签发兜底。
- 既有 /account/session 严格成功体保持兼容；生产验证的基础设施错误返回503，旧客户端已识别为 unavailable。新认证接口采用主规格 envelope。
- 新方案替代旧邮箱验证码直接登录与未批准 Supabase 试点；验证码用于注册验证，后续密码登录，Apple 分包接入，微信延期。

## Risks / Trade-offs

SA-08 家庭基础：成人明确创建家庭；同一家庭至多一个 active owner，同一成人可创建多个家庭。请求键按主体保存摘要并与家庭/owner 成员关系同事务提交。查询只返回当前有效成员；仓储可在调用方事务中从真实数据库装配家庭策略快照，当前没有共享记录 grant，不能据此批准记录或房间操作。邀请、监护与儿童设备单独接线和验收。

SA-08 邀请：owner/admin 基于当前家庭与成员版本创建 24 小时令牌，令牌由服务端生成，数据库保存 HMAC 摘要；同键恢复需要加密保存受限响应。创建和接受均用已验证成人会话，接受时重新检查邀请者权限及版本。指定邮箱必须是接受者自己的已验证登录邮箱；未指定邮箱的令牌是受控的家庭成员邀请，仍需持有人登录并一次性消费，不是房间公开码。接受只添加 `member`，不派生监护、记录、白板或录像权限。密文在消费、过期时清理。

SA-08 儿童设备服务端：0011 增量迁移独立保存同意、监护关系、双秘密配对、设备授权及会话外键；0012 以增量方式将 30 天约束修正为精确 720 小时，不改写已应用的 0011 校验和。只有当前 owner/admin 能在明确同意下创建 child 与监护关系；家庭角色不替代该关系。家长儿童列表只返回当前有效监护关系对应的最小摘要。匿名申请 5 分钟、双令牌分离并限流；家长以成人会话和当前实际监护关系预览服务器保存的设备描述及拟授权儿童，再用 `approve-child-device` 再次验证批准，记录批准时的关系和凭据版本；发起设备用 pollSecret 一次领取，原子创建 30 天 grant 和受限 child 会话。首批 grant 的 `scopes=[]`，不能凭家庭成员关系读取成人家庭摘要，也不取得房间/白板对象授权。每次 child 验证/刷新都实时检查 grant、关系、同意、家庭及版本；撤销也在同事务失效关联会话。配对完成响应只允许在 60 秒内且原 refresh 未轮换/撤销时恢复；密文与儿童创建幂等记录按期清理。共享客户端已提供双凭据隔离、审批前预览、家长儿童列表和受限轮询；移动端控制器已接入领取、会话持久化、家长预览及密码/Apple 动作绑定批准。正式配对界面、原生设备体验和房间/白板权限仍单独验收。

SA-08/09 房间席位预备内核：0013 增量迁移只建立房间及以服务端会话为键的五席位表；事务内行锁和活动席位唯一索引限制并发超额。该内核没有公开路由，调用方仍必须在同一事务先完成真实会话、家庭、房间邀请和对象授权校验。现阶段不签发 RTC 凭据，不推断重连保留时长，不把席位行当成加入或白板编辑凭据；正式 9.4/SA-09 另行验收。

Apple-only 家长批准儿童设备：0014 只扩展 Apple reauth 的动作白名单以签发 `approve-child-device` grant；flow 仍绑定当前会话、主体和具体动作，实际配对批准仍由监护关系与一次性 grant 同事务裁决。当前合成 Apple 与隔离数据库 HTTP 验证不等于原生 Apple 或真实设备验收，见[证据](../../../docs/evidence/backend-auth-apple-child-approval-2026-09-24.md)。

SA-07 注销前置：0015 在可恢复主库内建立删除作业和受限回执摘要；独立账本与 0018 主库围栏保存防复活标记及已重放水位。运行时已有只读的本人影响清单和回执状态路由；配置账本时启动先对账、重放并核验围栏，运行期间若账本水位前进也在维护周期先恢复再清理，逐次会话操作查询账本。内部无家庭依赖受理内核按 `prepare` → 主库提交 → `markAccepted` 排序，但正式注销提交路由仍关闭。后台每 30 秒运行受账本授权约束的服务端资料清理。维护者已确认多家庭逐个选择处置方式、接收人有效成人成员资格及其明确接受责任、唯一管理者结束管理且仍有其他成员时冻结家庭并撤销儿童设备授权、保留共同作品待核对；逐家庭事务处理和真实 Apple 撤销验收仍未闭环。旧备份若缺少已受理作业，启动保持关闭，不把防复活当作清理完成。进度合同的 `serverDataDeleted` 仅指思玥服务端管理的数据，不代表本机或其他离线副本已清理；见[证据](../../../docs/evidence/backend-auth-deletion-groundwork-2026-09-24.md)。

后续增量：0016 新增持久 Apple 撤销队列，0017 允许 Apple-only 账号取得绑定 `delete-account` 的再次验证 grant。供应商适配器、有限重试状态机与持久队列均只通过合成凭据和隔离数据库测试；队列尚未被正式运行时调度，Apple 真撤销与用户端完成通知未验收，不因此开放提交接口。
0019 增加队列授权重试时间：未获独立账本授权的领取保留密文并限时延后，批量协调也只写账本授权的删除作业；配置 Apple 与账本的运行时已调度此队列。真实进程 Playwright 以本地假供应商验证旧队列不外发、合法队列继续执行。真实 Apple 接口、失败通知和完整家庭处置未验收，提交接口仍关闭。

SA-07 家庭转交与冻结增量：0021 在主库保存接收人本人对管理及适用监护责任的 24 小时确认，绑定家庭、原 owner、双方成员版本及儿童范围摘要；预览只返回儿童数量而不泄露其身份。0022 为仍有其他成员的冻结家庭保存待处理记录，每个家庭最多一项未结记录。内部受理事务逐家庭执行已确认的转交或结束管理冻结，原子处理儿童授权、邀请、房间和注销作业；冻结家庭的 owner、成员及监护记录留待核对，服务端清理不将其标为已删除。启动与运行中恢复门禁只对匹配作业、删除中主体和冻结家庭的待处理记录允许这些关联留存，其他残留权限及孤立监护同意仍拒绝开放。正式注销入口在冻结后处理、恢复旧备份的家庭转交一致性、客户端交互和真实 Apple 撤销闭环前继续关闭。

SA-07 非 owner 退出增量：成人非 owner 成员选择结束本人访问时，内部受理事务只撤销其本人家庭成员资格、监护关系与同意、儿童设备授权及未结邀请／配对／房间权限，家庭保持 active，不创建冻结待处理记录。若其监护的儿童没有另一位有效监护人则拒绝；跨家庭的另一监护资格检查锁定关系、同意、主体、家庭及成员行，避免并发冻结后仍按旧快照通过。该内部步骤尚无正式注销入口；不能把它推广为唯一 owner 或唯一监护人的自动处理规则。

SA-07 空家庭增量：唯一 owner 结束管理时，若家庭从未有其他成员，且邀请、监护、儿童设备、房间、接收确认及冻结待处理等所有已建家庭关联表均无记录，内部受理在同一事务删除本人的创建幂等记录、成员行与家庭行；有历史成员或任一资源则拒绝，不凭当前活跃人数推断可删。资料清理增加已失效家庭成员行的删除；若此前标记服务端数据已删，后续再次发现家庭依赖则撤回该标记。尚存的邀请、监护、设备和房间历史关联需完成数据用途与保留边界核对，不能把本切片当作完整资料删除验收。

SA-07 历史数据门禁：资料清理区分当前权限依赖与已撤销但仍关联注销者的历史记录。后者不阻止受理，但在家庭邀请、监护同意／关系、儿童设备授权／配对、已结束房间、已解散家庭或冻结处理记录仍持有本人 ID 时，不盖 `serverDataDeleted` 完成标记；待明确清理或有界脱敏规则后才可继续。最小主体墓碑、独立防复活账本及有界安全审计另按其原用途保留，不把这些保留项与未处理的家庭历史混为一类。

60 秒恢复窗口内双凭据泄露可能恢复后继，因此短期加密并定期清理，不宣称设备绑定认证。同 PG 实例仍有资源及高权限角色风险，真实旧服务权限核验留待部署授权。已安装 PostgreSQL 17.11 并以隔离临时实例完成首批测试，生产权限与容量仍待核验。

## Migration Plan

隔离 provision → 空库/重跑/checksum/角色负面测试 → 会话并发与丢响应恢复 → HTTP 与旧合同回归。生产属于 SA-10，另行授权；不执行破坏性 down migration。

## SA-04 邮箱实现细化

沿用主规格第9章与14.5。追加迁移建立邮箱唯一约束、密码、挑战、Outbox、幂等、限流与最小安全事件。登录在行锁外验证密码、事务内复查主体和凭据版本；注册／重置先验证挑战再在受限事务内生成密码哈希，避免未验证请求先消耗哈希 CPU。持锁哈希受进程并发与3秒队列上限约束，本地通过不替代目标机器压测。锁顺序统一为主体→挑战／会话；已知账号的 request 先锁主体，再替换挑战。错误次数通过已提交结果返回，避免抛异常回滚计数。

Argon2id 采用64MiB/3/1，进程内最多2个运行、4个等待、等待上限3秒；未知邮箱执行同参数 dummy verify。默认邮箱发送5/小时、10/日、间隔60秒；额外 IP 20/小时、全局100/小时。确认错误/请求预算独立于挑战，登录预算按邮箱和IP累计；这些是保守工程初值，部署容量另验。

邮件先提供受控 SMTP 适配，不选择或申请新外部厂商；配置前关闭。仅独立 worker 发信，不在API事务持锁期间访问邮件服务。固定模板提供中英验证码和密码修改提示，不开放任意收件内容代理。SMTP 无服务端幂等保证：已知提交失败可有界重试，结果不明及失联发送租约变为 uncertain 并销毁载荷，不盲目重发；Message-ID 只作跟踪，不宣称其保证去重。

公开request必须有Idempotency-Key，规范化载荷用独立pepper HMAC；24小时元数据、60秒加密响应恢复。注册confirm的幂等恢复仍核验会话有效且初始refresh未消费；缓存失效后明确要求登录，不返回陈旧凭据。原始方案不改写。

本批实现与限制见 [SA-04 本地验证](../../../docs/evidence/backend-auth-email-2026-09-21.md)。SMTP 适配不是服务商选型决定，真实发件仍未验收；主方案原件保持不变。

## SA-05 客户端实施

复用既有 `/account/session` 严格合同，新增 typed auth client 支持部署前缀，不改变旧客户端的兼容行为。移动使用 expo/fetch 和已安装 SecureStore；桌面主进程使用 fetch 与 safeStorage。UI 和白板不直接持有恢复凭据或构造带身份的任意请求。

一个宿主仅有一个认证协调器：内存 access，安全包保存版本、固定环境／地址、installationId、当前 refresh／会话引用和待轮换 ID。刷新先落盘请求 ID，后落盘后继；所有持久化串行化，保存确认前不发布 authenticated。新账号意图增加 generation 并中止旧请求，迟到结果不得更新新账号状态。安全包损坏不初始化为空包。

离线退出先把 active 置空并保存最多4条仅供撤销的证明，再显示本机退出。队列满时明确要求联网清理，不丢弃撤销证明，不复用为登录。云退出结果与本机退出分开报告。原本未登录本地空间仍保留，其与云账号的显式映射另验收；不自动上传或改 owner。

SA-05 回归中修复既有桌面关闭竞态：编辑器仍须先完成保存才能正常返回，可信卸载通知解除已发出的关闭等待，不能让主进程等待已移除的回调；不改变保存失败保留编辑器的原预期。修改与失败／复验记录统一见 [本批证据](../../../docs/evidence/backend-auth-client-2026-09-22.md)。

### SA-05 空间接线核对（2026-09-22）

原方案所说的“沿用空间映射”不能理解为此分支已有生产映射仓储。实际 `PersonalSpace` 只有 id/name，SQLite 以固定 `local-owner` 初始化；移动 `getClient()` 缓存一个本地客户端，Electron 主进程也只构造一个。当前账号登录未改变它们，故这些内容仍是设备本地空间，不是已隔离的云账号缓存。

下一批需要一并接入的真实边界：

- `packages/adapters/src/sqlite-store.ts`、`apps/mobile/src/native-client.ts` 与桌面主进程：持久记录 environment/subject/space 关联，以受控命令显式创建／选择账号空间，保留既有 spaceId 与业务 owner；禁止仅把邮箱拼成 owner 或自动重写历史记录。
- `apps/mobile/src/client.ts` 与 `createLocalClient`：空间切换不能只替换界面上的账号名；旧客户端、待执行请求、缓存、生成任务与迟到结果都须受同一代际边界约束，原空间回执仍留在原空间。
- Excalidraw 正式存档使用 `packages/whiteboard/src/protocol.ts` 的固定 KEY；移动宿主 `whiteboard/native-service.ts`、桌面宿主 `main/whiteboard.mjs` 仍是本机命名空间。账号空间需要独立命名空间和拍照原件目录；切换前须落盘/显式失败，旧 DOM session 不可写入新空间。不能误用已隔离的旧自研 `whiteboard/storage.ts` 作为当前接入点。

以上为已核实的待实施范围，不是空间隔离验收；不得因此勾选任务6.4或宣称换号可查看云端作品。原本未登录本地空间的映射必须可见且可恢复，生产同步及自动上传不在此接线中自动启用。

### SA-06 Apple 验签首批

复用锁定 jose 6.2.12，不新增算法实现。Apple 身份 RS256 与思玥 access/Apple client-secret ES256 分开；固定 Apple JWKS URL，5 秒取钥超时、30 秒刷新冷却、10 分钟缓存。期望 client ID 来自可信服务配置，不接受请求选择。nonce/state/transactionSecret 均按32随机字节的43位 base64url 合同；事务保留 nonce 摘要，验签后恒时比较。JWT 16KiB 上限、必需 claims、60秒时钟容差及10分钟 token age 上界；后续5分钟一次性事务期限仍独立验证。

首批核查时只有 login 请求契约与身份验证函数，没有对外 start/complete 接线，link/reauth 当时未接入；此段是历史状态，后续服务端 `reauth + link-identity` 与邮箱绑定增量见 [2026-09-24 证据](../../../docs/evidence/backend-auth-identity-link-2026-09-24.md)。Apple provider 当前仍默认关闭，真实供应商、客户端绑定 UI 与设备验收未完成。姓名仅可选展示资料，不接受客户端邮箱/user/subject 作为身份。首批证据见 [Apple 验签记录](../../../docs/evidence/backend-auth-apple-2026-09-22.md)。

Apple code exchange 适配器已新增，仍未接公开路由。使用5分钟 ES256 client-secret、固定 token URL、拒绝重定向、默认10秒总响应/验证期限和32KiB响应上限；网络或响应不确定统一要求重新授权，不重试已发送代码。HTTP400/401记录 rejected，其余未知结果为 unknown，返回身份不符为 invalid_identity；均不创建会话。flow 仓储必须先校验并认领交易，再在事务外调用适配器，verified结果持久化后才能完成身份/会话写入。

Apple flow 存储追加0003迁移，复用现有角色和事务工具。pending→exchanging(30秒且不超过总5分钟)→verified；failed/expired为终态。秘密、state、nonce只存摘要，验证结果使用已有可轮换AEAD及flow/client AAD。认领绑定服务端计算的完成请求摘要与预验签subject。租约到期不重新认领，错误作为事务结果返回后再抛出，避免回滚失败标记。verified只代表上游证明已持久化，尚不代表思玥账号或会话完成；completed与60秒会话响应缓存将在原子账号完成接线时追加。定时清理仍需由宿主调用：过期敏感载荷清空，过期一天的流程删除；当前未启用公共入口。

登录准备服务现已串联 inspect→verify→claim→exchange→recordVerified→durable read-back。inspect先验证流程证明，避免无权请求触发外部验签；请求摘要绑定规范化幂等UUID及完整合同输入。交换在数据库事务外执行；写入后响应丢失时保留verified，可恢复且不重兑。尚未持久的结果不向下一阶段返回。该服务仅内部使用，公开provider仍关闭；身份与会话原子完成及60秒最终响应缓存仍待接线。

身份存储追加0004：以(provider,namespace,provider_subject)数据库唯一约束及事务级advisory lock串行首次创建，不以姓名/邮箱关联。已有身份按subject→identity顺序锁定，拒绝非active成人或非active身份；姓名仅用于首次创建。Apple refresh使用独立凭据表及identity/namespace AAD加密，调用者事务回滚时身份与主体一起回滚。该内部adapter只接受已验证的交换结果，尚待与flow完成及会话事务连接。

登录准备请求摘要按原方案14.5修正为服务端32字节pepper的HMAC-SHA256，带apple-login用途域；不能用进程随机pepper替代稳定服务配置。五分钟verified载荷是待完成交易的内部上游材料，既不作为公开响应，也不等于完成后的思玥会话恢复缓存；后者必须在原子完成时另加最长60秒期限。

0005增加completed状态、完成会话引用、完成时间及加密响应/独立到期时间。内部login-service先recover，再prepare，最后在flow行锁事务内调用identity resolve和session issue；并发首次恢复未命中后可再次读取另一请求已完成的结果。完整锁顺序为flow→identity advisory→subject→identity→session→refresh。回滚保留verified供重试，成功清除verified密文并写入最多60秒的思玥响应缓存。恢复检查subject状态/类型/凭据版本、session期限/撤销和原refresh摘要/消费/撤销，并在等待锁后再次核对期限。

五分钟期限约束授权和首次完成，已成功完成的响应恢复从完成时间起计60秒，即使跨过原授权期限也不重新兑换或签发；清理只清空响应，不把completed退回可创建状态。24小时后删除流程元数据；独立身份和会话不删除。真实路由、限流/审计、错误映射、生产配置及原生SDK仍待接线，因此provider未开放。平台与设备标签由已保存的start上下文写入会话。

### 2026-09-25 真实线上邮箱注册闭环
